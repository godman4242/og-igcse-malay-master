## Decision log
- **Pure model** `alongEdgeRectForZone(zone, boxSize, viewport, origin, margin)` in `dragDock.js`: edge
  slides on its long axis (cross axis pinned to the dock margin via the centred snap), corner stays
  pinned, `origin==null` (keyboard dock) ⇒ centred snap, non-finite coord ⇒ centred that axis, always
  clamped on-screen. *Veto:* store absolute clamped top-left (not a fraction) — simplest "holds across
  Next/Back"; keyboard dock stays centred so the deterministic Tdim★/Tpause★ keyboard e2e are unaffected.
- **Two clobber bugs found live (browser-verified):**
  1. `dock`/`reapplyDock` measured `offsetWidth` BEFORE the `guide-docked` class → clamp used the wide
     floating width (~308px → maxX≈70), collapsing every off-centre drop to one x (e2e: leftPos==rightPos==70).
     Fixed: reorder to **applyDockClass → measure → position**, and **remove the `.guide-docked`
     `max-width:0.15s` transition** (it made the shrunk 220px width unreadable synchronously; cosmetic only,
     already off for reduced-motion).
  2. driver.js re-positions the popover to each step's spotlight SYNCHRONOUSLY right after `onPopoverRender`
     (`driver.js.mjs:299` `x(t,…), ae(e,o)`), clobbering `reapplyDock` → docked box jumped to each step's
     spotlight (latent shipped bug). Fixed: re-stick the dock on the next `rAF` (after driver's reposition),
     teardown-guarded + gated on `dockedZone`.
