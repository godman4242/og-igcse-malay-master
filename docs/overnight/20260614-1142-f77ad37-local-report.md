## Decision log
- **Pure helper vs inline ternary fix.** Decision: extract `cardSidesFor` into the existing pure
  `selectionToCard.js`. Why: real behavioural coverage (the existing locale test is a weak source-grep),
  single source of truth alongside `glossPlanFor` (mirrors the repo's pure/impure split philosophy),
  proves the ms-byte-identical claim. Veto note: if it had needed new infra it'd have been over-engineering,
  but `selectionToCard.js` already holds `normalizeSelection`/`detectLanguage`, so it's the natural home.
- **Signal: `studyLang` (global) vs per-word `detectLanguage`.** Decision: card DIRECTION follows
  `studyLang` (the queue directive); TRANSLATION still uses per-selection `detectLanguage` (so the gloss is
  always right). Why: `studyLang` is the v34 deck-partition signal; both selection languages then produce a
  correctly-directed card for the active deck. Veto: an en learner selecting a Malay word still yields a
  valid English card (m=English gloss, e=Malay term).
