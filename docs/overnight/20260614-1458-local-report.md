## The fix

`cikguKnowledge.js:78`, the `be-` variation bullet in the `imbuhan-ber` answer (rendered verbatim by
`formatKnowledgeResponse`):

```
- **be-** → before r + consonant: bekerja (NOT berkerja), berenang
```

→

```
- **be-** → when the root starts with **r** (renang → berenang), or its first syllable ends in **-er** (kerja → bekerja, NOT berkerja)
```

**Why it was wrong:** "before r + consonant" conflates two *distinct* allomorph rules under one
inaccurate label and mis-describes both examples:
- `bekerja` = ber- + **kerja**, whose first syllable "ker" ends in **-er** → be- (the -er- rule).
- `berenang` = ber- + **renang**, whose root **starts with r** → be- (the r-initial-root rule;
  renang is r + vowel, NOT "r + consonant").

This is the same conflation already grounded-and-fixed in `grammar.js` (the `berasa` ruling:
`be- + r → r drops` for r-initial roots vs the `-er-` first-syllable case). The forms were correct;
the **taught rule** was wrong — a confident-wrong grammar lesson, the worst failure for a learning tool.

**Decision / why / veto:** rewrote the single bullet to name both web-verified conditions accurately,
each example under the right condition. *Veto:* considered leaving it (a prior cycle deferred it as
"imprecise, not clearly wrong") — but that deferral was pending a grounded ruling, which is now in hand
(web + the app's own grammar.js precedent); also considered splitting into two bullets — rejected as a
larger diff that breaks the entry's one-bullet-per-variation structure.
