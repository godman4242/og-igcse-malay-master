# 2026-05-27 — Session: 401 bug fix + handoff cleanup

## Context

Previous session (2026-05-26) shipped Adaptive Scaffolding (Master Plan
#3). User deployed `supabase functions deploy ai-proxy` afterwards but
the working-copy diff was never committed. Subsequent smoke-test curl
on 2026-05-27 returned `UNAUTHORIZED_INVALID_JWT_FORMAT`.

User's resume note flagged this as a P1 guest-only bug at
`src/lib/ai.js:151`, with three candidate fix paths.

## Diagnosis

Three things converge:

1. `supabase/functions/ai-proxy/config.toml` has `verify_jwt = true`.
   Supabase's gateway rejects anything that isn't a real JWT *before*
   function code runs.
2. `.env.local` ships `VITE_SUPABASE_KEY=sb_publishable_*` — Supabase's
   new key format (2025 rotation). Not JWT format.
3. `src/lib/ai.js:151` set `let authToken = SUPABASE_CONFIG.key` as a
   fallback for guests. The gateway rejects this token with
   `UNAUTHORIZED_INVALID_JWT_FORMAT`.

**Not just guest-only:** `getSupabase()` is the *sync* getter on a
module-level `supabaseClient` that's only set after `initSupabase()`
resolves. AuthGuard lazy-imports + initialises supabase on mount, so
on cold load there's a window where logged-in users hit the same
fallback and 401.

**Bonus broken path:** `callEdgeFunction()` at `src/config/supabase.js:373`
hardcoded the publishable key. Dead code — nothing called it — but
would have 401'd anything that revived it.

## Fix path chosen

Option C variant — keep `verify_jwt = true` (no infra change), require
a session JWT in the client, refuse cleanly when guests try AI.

Rationale over alternatives:
- `--no-verify-jwt`: opens function to the world; only IP rate limit
  + CORS as cost-control. Worse security than current state.
- Server-side publishable-key check: doesn't work without disabling
  `verify_jwt` first (gateway rejects before function code). Equivalent
  to A with extra plumbing.
- Shared-secret header: secret has to ship in the client bundle (VITE_
  env vars inline at build time). Same security level as the
  publishable key it would replace — security theatre.
