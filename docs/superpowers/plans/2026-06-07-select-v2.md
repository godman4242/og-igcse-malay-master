## Step 2 — group / ungroup + the compositional teaching-moment (TDD core, then wire)
The payload of Kheshav's idea: *see how meaning changes when words connect* (jam + tangan → watch).
- **Pure (TDD) — `src/lib/selectionGroup.js`:**
  - `groupSelection(selection, fromIdx, toIdx)` → replaces the covered CONTIGUOUS `word` entries
    with one `{ word: joinedSpace, type:'phrase', startIndex, endIndex }` (drop per-word `en` so it
    re-translates). `ungroupSelection(selection, idx)` → splits a phrase entry back into word
    entries (re-deriving indices). Pure; idempotent; group-of-one = no-op; non-contiguous = ignore.
  - Tests `__tests__/selectionGroup.test.js`: group 2 adjacent words → 1 phrase entry; ungroup
    reverses; group-of-one no-op; preserves other entries + order; indices stay consistent. RED→GREEN.
- **Teaching-moment (pure-ish):** `explainCompound(parts[], partGlosses[], phraseGloss)` →
  a small view-model `{ parts:[{w,gloss}], phrase:{w,gloss} }`. Test the assembly.
- **Wire (PDFReader):** when a phrase is formed (right-drag OR the bucket "group" button), fetch
  BOTH `translateMany(parts)` and `translatePhrase(whole)`, then render in the **translation panel**
  (~L328) an extra block: `jam = o'clock · tangan = hand → **jam tangan = watch**`. Add a tiny
  group/ungroup toggle on bucket chips (~L393).

## Step 2.5 — TOUCH support (the go-wild finding — REQUIRED, app is mobile-first)
PDF select is mouse-only → inert on phones. Make it work on touch:
- Add `onPointerDown/Move/Up` to `useSelectionMode` (Pointer Events unify mouse+touch+pen).
  Keep the existing mouse `button` shortcut for desktop; on touch there's no right button, so the
  intent comes from a **toolbar toggle** "Group ⟷ Individual" (default Individual), shown when
  `mode==='select'` (~L308). `classifyGesture` gains an optional `touchIntent:'words'|'phrase'`
  param that wins when `button` is undefined/0 on a touch pointer (TDD: pointer+drag+toggle →
  expected kind; mouse path unchanged — extend `gestureModel.test.js`).
- Guard scrolling during a token-drag (don't hijack a normal scroll): only begin a selection drag
  when `pointerdown` lands on a `[data-token-i]` (the hook already hit-tests that); call
  `setPointerCapture` so the drag tracks. Verify a plain scroll still scrolls.
- A "group" action phones can actually perform (the toggle, or a bucket "Group selected" button)
  is REQUIRED before shipping.

## Step 3 — inline selection highlight (delivers (b))
- **Close the index gap:** in `handleCommit`, attach indices to bucket entries — add
  `tokensSliceWithIndex(a,b)` (→ `[{word,i}]`); for `kind==='words'` push `{word,type:'word',
  index:i}` per token; for `phrase`/`word` push `{…, startIndex, endIndex}`. Update
  `groupSelection`/`addSelectionToDeck` to tolerate the new fields (they ignore extras).
- **Derive the highlight set:** `const selIdx = useMemo(()=>{ const m=new Map(); for(const e of
  selection){ const a=e.startIndex??e.index, b=e.endIndex??e.index; for(let i=a;i<=b;i++)
  m.set(i, e.type) } return m }, [selection])`.
- **Render (~L428):** when `selIdx.has(p.i)`, add a background — word = `var(--color-accent-subtle)`,
  phrase = the purple phrase tint — PLUS a non-colour cue for a11y (phrase tokens get
  `borderBottom: '2px solid var(--color-purple)'` so a grouped unit reads as one even without
  colour; `title`/`aria-label` "selected" / "grouped phrase"). Keep `tokenColor` as the TEXT
  colour so vocab tint + selection background compose.
