## Step 1 — pure `classifyGesture` (TDD)  ← do first, no DOM
Extract the gesture→intent decision out of the DOM hook into a pure function so it's testable
(this is exactly where the current invert-bug hid).
- New `src/lib/gestureModel.js`: `classifyGesture({ button, startIndex, endIndex }) →
  { kind: 'word' | 'words' | 'phrase' }` per the CONFIRMED Q1 mapping. (Default recommend:
  `button===0 && a!==b` → `'words'` (individual); `button===2 && a!==b` → ... see Q2; single
  → `'word'`.) Keep `a=min,b=max` (backwards-drag) inside the classifier.
- Tests `src/lib/__tests__/gestureModel.test.js`: every (button × drag/no-drag × backwards)
  combo → expected kind; single-token group is a no-op; garbage indices tolerated. RED→GREEN.
- Refactor `useSelectionMode.js` to call `classifyGesture` (thin DOM adapter). Keep its
  existing handlers; just swap the inline boolean logic for the pure call. Verify the
  PDFReader `handleCommit` switch still maps each kind correctly (rename `isPhrase/isMulti`
  → the `kind` string to kill the inverted-flag confusion).

## Step 2 — "group into a phrase" action (TDD-able pure part)
Per Q2 (default = right-click on an existing selection):
- Pure helper in `gestureModel.js` (or `selectionToCard.js`): `groupSelection(selection,
  fromIndex, toIndex)` → a new selection array where the covered contiguous WORD entries are
  replaced by one `{ word: joined, type:'phrase' }` (drop the per-word `en` so it re-translates).
  `ungroupSelection` reverses (split on space back to words). Pure. Unit-test both, incl.
  group-of-one = no-op, non-contiguous = ignore, idempotence.
- Wire into PDFReader: a right-click handler on the selection (or selected token range) calls
  `groupSelection`, then re-runs `translatePhrase` for the new phrase entry. §2 teaching
  moment: when grouped, also fetch `translateMany(parts)` and show "jam = … · tangan = … →
  **jam tangan = …**" in the bucket chip / a small popover.

## Step 3 — inline selection highlight (delivers (b))
- In PDFReader token render: maintain a `Set` of currently-selected token indices (derived
  from the `selection` bucket's word spans, or a live `selectedRange`). Give those `<span>`s a
  background `var(--color-accent-subtle)`; grouped-phrase tokens get the purple phrase tint +
  an underline bracket (border-bottom) so the unit is visually one thing.
- Keep `tokenColor` (vocab status) as the TEXT colour so it composes with the background.
- a11y: the selected/grouped state must not rely on colour alone — add an `aria`/title cue
  ("selected", "grouped phrase") and the underline bracket as the non-colour signal.
