# Multimodal study inputs — OCR + audio transcription (free, on-device)

> Reference doc — read this when touching the photo/scan OCR path, the "study from a recording" audio path, or the BYOK-vision "Sharper read". Pointer lives in `CLAUDE.md` → Architecture. Both are alternative **producers of the reader's `{pages}` shape**; the gloss→FSRS core is untouched.

## Past-paper OCR (free, on-device)

Photograph or upload a printed past-paper page (an image, or an image-only/scanned PDF) and study it in the **same** reveal-gated reader — the **gloss→FSRS core is untouched**. Two layers mirror `translateDocument.js`'s testable pattern: **`src/lib/ocr.js`** is pure (no DOM/network/WASM) — `runOcr(images, {recognize})` takes an **injected** engine and emits the reader's exact `{pages:[{pageNum,text,paragraphs}]}` shape (so OCR is just an alternative producer of `{pages}`); **`src/lib/ocrEngine.js`** is the only impure boundary — a **lazy** `await import('tesseract.js')` (Tesseract.js 7, `oem:1` LSTM-only, `createWorker(langs, oem, options)` confirmed v7) behind `createOcrRecognizer()`. Assets are **self-hosted** under `public/ocr/` (image NEVER leaves the device): `scripts/copy-ocr-assets.mjs` (prebuild+postinstall) ships only the 6 LSTM WASM core variants (~20 MB, gitignored, regenerated from the dep) + worker; the `tessdata_fast` `msa`/`eng` models are committed gzipped (~3 MB, no CI fetch). PWA: `/ocr/**` is excluded from precache (`globIgnores`) and runtime-`CacheFirst`-cached (offline after one run). `PDFReader.handleFile` branches on `file.type`: an image → `runImageOcr` (forces reflow — image sources have no `pdfDoc`, so the Layout toggle is gated on `pdfDoc`); an `isImageOnlyPdf(pages)` PDF → a **non-punitive OCR offer** (rasterise via `renderPdfPageToCanvas`, capped at 10 pages). OCR is a **draft the learner verifies**: low mean word-confidence (`<70`) shows a dismissible blurry note, and per-word low-confidence carries a dotted-underline cue (by surface string — no edit to the grounding/gloss core). Spec/plan: `docs/superpowers/{specs,plans}/2026-06-11-past-paper-photo-ocr*`.

## Audio transcription — "study from a recording" (free, on-device)

Upload or record an audio clip and study its transcript in the **same** reveal-gated reader — the **gloss→FSRS core is untouched** (audio is just another producer of `{pages}`, exactly like OCR). Two layers mirror `ocr.js`'s testable pattern: **`src/lib/transcribe.js`** is pure (no DOM/network/WASM) — `runTranscribe(audio, {transcribe})` takes an **injected** engine and emits the reader's exact `{pages:[{pageNum,text,paragraphs}]}` shape; `isSilentSamples` gates no-speech audio to the empty state (Whisper hallucinates subtitle credits like "Terima kasih kerana menonton!" on silence). **`src/lib/transcribeEngine.js`** is the only impure boundary — a **lazy** `await import('@huggingface/transformers')` (Whisper ASR pipeline, `dtype:'q8'`, Web Audio `decodeAudioData`→16 kHz mono) behind `createTranscriber()`, run **on the main thread** for Phase 1 (Web Worker is the #1 follow-up). `PDFReader.handleFile` branches on `audio/*` → `runAudioTranscribe` (forces reflow; audio has no `pdfDoc`). **⚠️ `@huggingface/transformers` is PINNED to v3 (^3.8.1) — v4.2.0's nightly ORT-web 1.26 deadlocks `pipeline()` in the browser (loads fine in Node); v3.8.1's ORT-web 1.22 works.** Model = `mesolitica/malaysian-whisper-base` → ONNX **fully int8 q8 (~103 MB)**, FLEURS WER Malay 20.1% / English 14.6%. Self-hosted under `public/asr/` (gitignored): `scripts/copy-asr-assets.mjs` (prebuild+postinstall) copies the ORT-Web wasm from node_modules + **fetches the model from the GitHub Release `asr-model-mesolitica-base-q8`** (git rejects >100 MB; the merged decoder is quantized by quantizing the un-merged decoders then re-merging — see `CONVERSION.md`). PWA: `/asr/**` excluded from precache + runtime-`CacheFirst` (offline N5; `useBrowserCache` is off so the SW is the sole /asr cache). The ASR e2e (`tests/e2e/audio-transcribe.spec.js`) runs against a **production `vite preview` server :4173** (ORT's wasm glue is a /public static asset Vite dev can't import; offline needs the built SW), with a preview-only `/asr` `no-store` middleware for headless's ERR_CACHE_WRITE_FAILURE on the large model. Spec/plan: `docs/superpowers/{specs,plans}/2026-06-13-multimodal-audio-transcribe*`.

## Phase 2 — the optional BYOK-vision "Sharper read"

(spec/plan `2026-06-11-past-paper-ocr-vision-rung*`): when the free read comes out rough, a **manual, consent-gated** button re-reads the SAME retained image(s) via the user's OWN vision-capable provider (Gemini primary / OpenRouter secondary; Ollama excluded) — it **uploads the page**, so it is disclosed three ways (button label "Sharper read — uploads to {provider}", a one-time consent dialog with "Don't ask again" = `pdfReader.visionConsent`, and a provenance banner on the result). Seam: **`callInstructVision`** in `instruct.js` routes ONLY to adapters with the additive `supportsVision`/`callVision` capability (an image can never land on a blind text model) and reuses the cooldown/auto-switch engine via the shared `runOnAdapters` loop — **`callInstruct` and every text caller are behaviour-frozen** (pinned by the untouched suites). `src/lib/ocrVision.js` (pure prompt) + lazy `src/lib/ocrVisionEngine.js` — `createVisionRecognizer()` is just a **second producer of `runOcr`'s injected `recognize` contract**, returning `words: []` so `meanConfidence===0` auto-suppresses the Tesseract blurry note/dotted cue (the banner replaces them). A failed sharper read NEVER blanks the free read. Vision free-model discovery: `pickVisionModels` filters `architecture.input_modalities ⊇ 'image'` and excludes reasoning models + the `openrouter/free` meta-router. Accuracy is a MANUAL harness (`scripts/ocr-accuracy-harness.mjs`, needs `GEMINI_KEY`), never a CI gate.
